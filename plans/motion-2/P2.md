# P2: Motion engine (1.0.0, with P1)

Goal: the JS half of the motion system becomes a real engine. `DS.motion` reads its timing from the computed tokens,
can be interrupted and continues from the current state (D21), knows when an element has settled, glides data (FLIP
and `countUp` from the shown value, D7), and gives later phases their shared helpers (`originFrom`, `travelDuration`,
`roll`, `crossfade`). `DS.dom.morphHtml` patches in place with keys and keeps focus and the indicator. A new `DS.ripple` adds the
pointer ripple (D6). The Playwright `fallback` project starts here.

Depends on P0 (harness, `test/browser/helpers/motion.js`, capability spike, the known-bug `test.fail` markers) and on
P1, which this phase does **not** redo: layers, the motion tokens (`--ds-dur-micro` ... `--ds-dur-long`,
`--ds-ease-spatial`, `--ds-ease-exit`, `--ds-ease-value`), `--ds-time-scale`, the registered
non-inheriting hooks (`--ds-motion-origin`, `--ds-clip-from`, `--ds-i`, `--ds-enter-*`, `--ds-leave-*`), movement
keyframes on the individual `translate` / `scale` properties, movement-only exits paired with `ds-fade-out`, the
`ds-press-ripple` keyframe, the ES2022 baseline with sibling imports in `scripts/build.mjs`, and the removal of
`prefersReducedMotion()`. If the P0 spike shows that the interruption mechanism below fails in an engine, the
fallbacks of the authority's risk table apply before any task here builds on it.

Ships: with P1 as **1.0.0** (D31). P1 and P2 are separate commits, pushed together after P2's checks pass. Every
behaviour change of an existing export lands here and is written into the 1.0.0 migration section.

Line anchors refer to `src/` at HEAD before P1; P1 moves some lines, so find the code by its name.

## Tasks

### Timing from tokens (`src/js/motion.js`)

- [ ] **T1** Timing readers.
  - `export function motionDuration(el, token)` returns ms. Outside a `.ds-theme` (`!el?.closest?.('.ds-theme')`)
    it returns the fallback (next bullet). Inside, it parses `getComputedStyle(el).getPropertyValue(token)`: `Nms`,
    `Ns`, and `calc(<time> * <number>)` (an unregistered token with `--ds-time-scale` substituted). Anything else
    goes through a cached hidden probe (`transition-duration: var(<token>)`, read back as seconds). The result
    therefore includes `--ds-time-scale`, so slow motion slows JS and CSS together (D12).
  - `export const MOTION_FALLBACKS`, a frozen object keyed by token name. It holds the ms of every
    `--ds-dur-*`, `--ds-delay-*` and `--ds-hold-loader`, and the cubic of every `--ds-ease-*`
    (`--ds-ease-spatial` → the `--ds-ease-out` cubic, `--ds-ease-emphasized` → its cubic fallback).
    `COUNT_UP_MS`, `LOADER_DELAY_MS` and `LOADER_MIN_VISIBLE_MS` stay exported and equal their entries.
  - `export function motionEasing(el, token)` returns the computed easing string (the fallback cubic outside a
    theme). `--ds-ease-value` resolves to `cubic-bezier(.2, 0, 0, 1)`.
  - `export function travelDuration(el, px)` is the one distance rule for FLIP (here) and the indicator (P4):
    `medium + (slow − medium) × min(1, |px| / 480)`, with `medium` and `slow` read through `motionDuration`.
  - Internal `animateSafe(el, keyframes, timing)` wraps `el.animate()`. On a `TypeError` (an engine that rejects
    `linear()`), it retries with the token's cubic from `MOTION_FALLBACKS`. Every WAAPI call in `src/js` goes
    through it.
  - Internal `curve(css)` returns `t => value` for `cubic-bezier()` (Newton with a bisection fallback), `linear()`
    (piecewise, percentage stops, values above 1 allowed), and the keywords `linear`, `ease`, `ease-in`, `ease-out`
    and `ease-in-out`. `countUp` uses it. It is not exported: P8 exports it if the Motion Lab plots need it.
  - The reduced-motion half of these findings is gone (D8, removed in P1).
  [core-js-motion-preference, js-motion-source-of-truth, js-countup-curve]

### Enter, leave and interruption (`src/js/motion.js`)

- [ ] **T2** One state per element. A module `WeakMap<Element, { gen, opener, handoffs }>`. `enter()`, `leave()`
  and the new `export function cancel(el)` each bump `gen`.
  - Every continuation (removing classes, hiding, removing, moving focus) first checks that its generation is still
    current. A superseded promise resolves without acting: no AbortError, so existing `.then()` chains still run.
  - An internal `clearMotion(el)` removes every class matching `/^ds-(enter|leave)(--[\w-]+)?$/`. It runs at the
    start of `enter()` and `leave()` and in the current generation's cleanup. So `enter('fill-x')` → `enter('scale')`
    keeps only the scale variant, and `leave('sink', {then:'keep'})` → `leave('scale')` keeps only the scale variant.
  - `cancel(el)` calls off pending continuations, cancels handoff animations, runs `clearMotion`, and clears the
    `inert` that `leave()` set. The element shows its rest state at once. It is the public way to take back a
    pending `leave()` without an entrance.
  [core-js-leave-enter-race, js-leave-enter-race, repo-leave-enter-race, js-variant-classes-linger]
- [ ] **T3** `enter(el, variant?)` (motion.js:100) clears `hidden` and `inert` before it plays, so an entrance after
  `leave(el, v, {then:'hide'})` runs at once instead of waiting for the timeout. It records the opener: the element
  that has focus when `enter()` is called, if that element is outside `el` and is not `body`. [core-missed-5]
- [ ] **T4** `leave(el, variant?, { then, focus })` (motion.js:115).
  - If `el.contains(document.activeElement)`, it first moves focus with `preventScroll: true`. The target is
    `focus` (an Element or `() => Element`), else the recorded opener, else the closest ancestor with
    `tabindex="-1"` (for example `.ds-view`), else it blurs. Only then does it set `el.inert = true` for the exit.
  - `then`:
    - `'remove'` (default) removes the element.
    - `'hide'` sets `hidden`, clears `inert` and the classes.
    - `'keep'` is now defined: the element stays in the DOM, invisible (the exit's forwards fill) and `inert`. It
      comes back only through `enter()` (which continues from there) or `cancel()`.
  [core-js-leave-focus, core-missed-4]
- [ ] **T5** Interruption from the current state (D21), with one mechanism. Internal
  `handoff(el, applyClasses)` is used by `enter()` and `leave()` whenever the element has an own `ds-*` animation
  that is running or holds a fill (a CSS animation or an earlier handoff):
  1. Snapshot the computed `opacity`, `translate`, `scale` and `clip-path`.
  2. Cancel the running own animations.
  3. Apply the new classes.
  4. Read the new CSS animations' names, durations and timing functions from the computed `animation-*` lists (by
     index), and their end values: the end keyframe of `effect.getKeyframes()` for an exit; for an entrance, the
     rest style read after the CSS animation is cancelled. Where the P0 spike showed an engine returning unresolved
     `var()` in `getKeyframes()`, the end values are read with the animation paused at its end before it is
     cancelled.
  5. Cancel those CSS animations and play `animateSafe(el, [snapshot, end], …)` per track:
     - id `ds-handoff`;
     - the new direction's curve: the exit curve when leaving, the entrance curve (the spring for movement) when
       entering;
     - duration = the token duration × the remaining share (from the fade track: current opacity for an exit,
       1 − opacity for an entrance; from the movement track when there is no fade), floored at
       `motionDuration(el, '--ds-dur-micro')`;
     - delay 0 (an interrupted run never staggers);
     - `fill: 'forwards'` for exits.

  Nothing is reversed, nothing restarts from 0 or jumps to 1, and no inline style is written, so the inline
  `transform` of a tooltip or an indicator stays intact. A second `enter()` during a running entrance continues the
  same way instead of restarting. [core-js-interruptible, js-interrupt-from-current]

### Settled, replay and batched entrances (`src/js/motion.js`)

- [ ] **T6** Rewrite `settled(el, { names, property, transitions, subtree, timeout, event })` (motion.js:77-91).
  - Primary path: `el.getAnimations({ subtree })` right after the class change (it flushes style). It keeps:
    - CSS animations whose `animationName` is in `names` (`enter` and `leave` pass the computed `animation-name`
      list of their own classes);
    - `ds-handoff` animations;
    - CSS transitions, but only when `transitions: true` or `event: 'transitionend'` (kept as an alias), filtered
      by `transitionProperty === property` when given.
  - It skips effects with a `pseudoElement` (state layers, ripples) and infinite iterations. It resolves on
    `Promise.allSettled(list.map(a => a.finished))`, so it waits for both tracks of a fade + movement pair, and a
    cancel counts as done.
  - The helper watches only the animations its own class change created, and the generation guard (T2) handles
    supersession. So a cancel of an older animation never resolves a newer wait, and `replay()` never needs
    `cancel()`/`play()`.
  - Empty list: check again on the next frame, then resolve. No more 1000ms wait on hidden or detached elements.
  - Ceiling: `timeout` if given, else max(delay + duration × iterations) / playbackRate over the kept animations,
    plus 100ms. This replaces the fixed `DEFAULT_TIMEOUT_MS` (it stays an internal constant, used only when nothing
    can be read), so a long `--ds-enter-delay` or `--ds-enter-duration` is no longer cut off.
  - Fallback without `getAnimations` (unit-test fakes): `animationend`/`animationcancel` (or
    `transitionend`/`transitioncancel`) counted per expected name. It ignores `evt.target !== el` and any
    `evt.pseudoElement`.
  - `subtree: true` serves the `.ds-view--leaving` swap fallback (P4/P7) and overlay code (P5).
  [core-js-settled-cancel, js-settled-robust, repo-js-settled-cancel, core-missed-2, repo-missed-4]
- [ ] **T7** `replay(el, ...classes)` (motion.js:61-67) removes the classes and flushes only when the element
  carries one of them. It flushes with `void getComputedStyle(el).animationName`, a style flush without layout that
  also works on SVG (no `offsetWidth`). [core-js-replay-svg-reflow, js-replay-svg, repo-js-replay-reflow]
- [ ] **T8** `export function enterAll(elements, variant?, { stagger = true, max = STAGGER_MAX, visibleOnly = true })`
  works in batches:
  1. One write pass: `clearMotion` on every element.
  2. One flush.
  3. One read pass: rects, only for `visibleOnly`.
  4. One write pass: `--ds-i` and the classes.

  With `visibleOnly`, items entirely outside the viewport at call time get no entrance: they show at rest and never
  animate later. It returns `Promise.all` of the items' `settled()` and removes `--ds-i` from every item afterwards.
  [js-enter-batch, core-js-replay-svg-reflow, repo-js-replay-reflow]
- [ ] **T9** `export function staggerOnce(container, { variant, max })` is the first-render stagger: `enterAll` on
  the container's element children (visible ones only).
  - It marks the container `data-ds-staggered`; later calls resolve at once without motion.
  - It cleans up its classes and `--ds-i` once the last child settled.
  - Fix the `stagger()` comment (motion.js:36-44): `--ds-i` is read only by `.ds-enter` and `.ds-stagger > *`, not
    by "every component that staggers".
  - Rewrite the example at `docs/motion.md:111-118`:
    - first load: `settleLoader` → `morphHtml` → `DS.motion.staggerOnce(list)`;
    - refreshes: `DS.motion.flip(list, (o) => DS.dom.morphHtml(list, html, o))` only.
  [core-docs-example, repo-docs-stagger-example]

### Values (`src/js/motion.js`)

- [ ] **T10** Rewrite `countUp(el, to, { from, format, duration, win })` (motion.js:170-189).
  - A `WeakMap` of running counts: a new call cancels the running rAF loop, so only one loop ever writes.
  - Start value: an explicit `from`, else the value on screen (also mid-count, which retargets seamlessly), else 0
    on the first call. The same value is a no-op, so a refresh that changes nothing does not count.
  - Counting down animates too.
  - Duration: `options.duration ?? motionDuration(el, '--ds-dur-glide')` (`COUNT_UP_MS` outside a theme). `0`
    writes at once.
  - Curve: `curve(motionEasing(el, '--ds-ease-value'))`, the curve of progress bars, so a figure and its bar land
    together. It never overshoots.
  - A non-finite target is shown at once. A disconnected element stops the loop and gets the final value, never an
    intermediate figure.
  - During the count:
    - `aria-busy="true"`;
    - a `min-width` through the CSSOM, the larger of the old and final strings' widths (measured once, removed at
      the end);
    - `font-variant-numeric: tabular-nums` set through the CSSOM when the computed value lacks it (kept, so the
      final figure does not shift).
  - Returns `{ cancel, finished }`. `cancel()` stops the loop and writes the target value; `finished` resolves when
    the final value is written.
  - `easeOutCubic` stays exported, documented as deprecated and no longer used.
  [core-js-countup-reentry, js-countup-concurrent, repo-countup-overlap, core-js-countup-a11y, js-countup-layout,
  core-missed-3, js-countup-curve, repo-countup-curve, js-missed-5]
- [ ] **T11** Loader timing options (motion.js:139-155).
  - `loaderHoldMs(startedAt, now?, { delay, minVisible })` and
    `settleLoader(startedAt, nowOrOptions?, { element, delay, minVisible })`. The positional `now` keeps working.
  - Defaults are unchanged (`LOADER_DELAY_MS`, `LOADER_MIN_VISIBLE_MS`).
  - New layer-1 scale `--ds-hold-loader: calc(450ms * var(--ds-time-scale, 1))` in `src/tokens.css`, before the
    `── 2. Palette` marker next to `--ds-delay-loader` (P1 does not add it), with a row in `docs/tokens.md`.
    `LOADER_MIN_VISIBLE_MS` mirrors it. T1's `MOTION_FALLBACKS` and every later phase read it from here.
  - With `element`, the delay is read from `--ds-delay-boot` when the element is or sits inside `.ds-boot`, else
    from `--ds-delay-loader`; `minVisible` comes from `--ds-hold-loader` (all through `motionDuration`, so they are
    time-scaled).
  - Fixes the boot flash: content ready at 300ms under a 400ms boot delay is held 0ms.
  [js-loader-delay-option]

### Helpers for later phases (`src/js/motion.js`, `src/motion.css`)

- [ ] **T12** `export function originFrom(trigger, panel)`. `trigger` is an Element or a `{ x, y }` point (a
  context menu at the pointer).
  - From the two rects it writes, through the CSSOM:
    - `--ds-motion-origin`: the trigger's centre projected onto the panel's border box and clamped to it, in px
      (`24px 0px`);
    - `--ds-clip-from`, with `round` and the panel's computed radius: `inset(0 0 100% 0 …)` for a panel below the
      trigger, `inset(100% 0 0 0 …)` above it, `inset(0 100% 0 0 …)` to its right, `inset(0 0 0 100% …)` to its
      left.
  - Returns `{ origin, side }`, with `side` one of `'bottom' | 'top' | 'right' | 'left'`.
  - P5 consumes it (menus, combobox, tooltips, dialogs) with `ds-clip-in` and the D17 scales. No per-component
    origin hooks.
  [core-css-origin-aware]
- [ ] **T13** `.ds-swap` and `roll()`.
  - `src/motion.css`, layer `ds.utilities`: `.ds-swap { display: inline-grid; overflow: clip; }` and
    `.ds-swap > * { grid-area: 1 / 1; }`. It is a slot where outgoing and incoming content cross without a width
    jump; P3's `crossfade()` and `.ds-icon-swap` build on it.
  - `export function roll(el, text)` swaps a status line inside `el` (which gets `.ds-swap`):
    - the old span plays `ds-fade-out, ds-roll-out` on the exit curve over `--ds-dur-fast`;
    - a new span plays `ds-fade-in, ds-roll-in` with the spring for movement over `--ds-dur-medium`;
    - the old span is removed once settled.
  - It is generation-safe: a roll during a roll continues from the current span (T5), and only the last text
    remains.
  - `export function crossfade(el, next, { kind = 'text' } = {})` (canonical JS API, 1.0.0): `el` gets `.ds-swap`;
    `next` (a node or a string) enters with `ds-fade-in` over `--ds-dur-fast` on `--ds-ease-in-out` while the
    current child leaves with `ds-fade-out` over `--ds-dur-instant` on `--ds-ease-in` and is removed once settled. No
    movement, no width measuring (the grid slot holds the width). Generation-safe like `roll()`. Any other `kind`
    throws a `TypeError` in P2; P3 adds `kind: 'icon'` on top of `.ds-icon-swap`.
  [core-css-missing-exits (a P1 id): its `roll()` part is done here]

### FLIP (`src/js/motion.js`)

- [ ] **T14** `export function flip(container, mutate, { items, live = false, max = 50, hold = 2000 })` (D7, D19,
  D21).
  - Measure (First) the items: `items` is a selector, default direct element children, without `data-ds-keep` and
    pending removals. `getBoundingClientRect` includes running FLIP offsets, so measuring first and then cancelling
    the items' running `ds-flip` animations retargets a FLIP in flight from where each item is.
  - Call `mutate({ holdOrder, onInsert, onRemove })`. The object can be passed straight to `morphHtml` as its
    options (T16, T18), and `holdOrder` is `false` for a normal run.
  - Measure (Last). Each moved item plays `animateSafe(item, [{ translate: 'dx dy' }, { translate: '0 0' }], …)`
    with id `ds-flip`, `composite: 'add'` (keeps an item's own translate), easing `--ds-ease-spatial` and duration
    `travelDuration(item, distance)`.
  - Inserted items enter with `enter(node, 'fade')`. Removed items (through `onRemove`) are lifted out of flow:
    `position: absolute` at their measured rect, with the container made `position: relative` while needed and
    restored after. They leave with `leave(node)` and are removed when it settles. For `<tr>` this follows the P0
    spike: where a row cannot be lifted, it is removed at once while the others glide (documented fallback).
  - Cap:
    - items whose First and Last rects both lie outside the viewport jump and are not counted;
    - when more than `max` items would move, the update runs without motion and running FLIPs are cancelled.
  - Live guard (`live: true`, D7):
    - It holds while a **mouse or pen** is over the container (the last `pointerType` is tracked from
      `pointerover`; touch never holds, because `:hover` sticks after a tap) or while focus is inside an item.
    - While held, it calls `mutate({ holdOrder: true, … })` at once (values patch in place, order, inserts and
      removals wait) and queues one coalesced reorder (the latest `mutate` wins).
    - The reorder runs as one FLIP on `pointerleave`, on `focusout` with no focus left inside, or `hold` ms after
      the first deferral.
    - A non-live call during a hold runs the pending reorder in the same FLIP: user actions glide at once.
  - Returns a Promise that resolves when the call's motion (or its deferred reorder) has finished.
  - Typing filters call it per keystroke; each call cancels and retargets, so no animations stack.
  [core-js-flip, repo-opp-flip-helper, js-morph-hooks]

### DS.dom (`src/js/dom.js`)

- [ ] **T15** Patch in place: `morphHtml(target, html, { replace, holdOrder, onInsert, onRemove })` and
  `morphChildren(target, nodes, options)`.
  - A matched element with the same tag (and the same key, or both unkeyed) keeps its node. Its attributes are
    synced (set the changed, remove the missing) and its children recursed, instead of replacing the subtree
    (`sameShell`, dom.js:17-26, stays only as the cheap equality test). Text nodes update `nodeValue` in place.
  - Runtime state survives a patch:
    - `class` keeps `ds-enter*`, `ds-leave*`, `ds-has-indicator` and `ds-pressed`;
    - `style` keeps the custom properties DS writes (`--ds-i`, `--ds-indicator-*`, `--ds-ripple-*`,
      `--ds-motion-origin`, `--ds-clip-from`) and re-applies them after the new style text.
  - Form controls that are not focused also get their `value`, `checked` and `selected` properties set from the
    changed attributes.
  - Escape hatch: `data-ds-replace` on a node (old or new) restores replace-on-change for that subtree, and
    `{ replace: true }` does it for the whole call.
  - So a `.ds-status--running` → `--ok` change keeps the span and its colour transition plays, and a new
    `--ds-progress` transitions instead of jumping.
  - Header comment of dom.js rewritten ("Kept nodes are never moved" is no longer true).
  [js-morph-attributes, repo-dom-morph-attrs]
- [ ] **T16** Keys.
  - The key is `data-ds-key`, else `id`. A keyed desired node is looked up among all old siblings, patched, and
    moved to its place: `moveBefore` where `typeof target.moveBefore === 'function'` (Progressive: keeps
    animations, focus and iframes), else `insertBefore`.
  - Two nodes with different keys are never morphed into each other.
  - `holdOrder: true` patches matched nodes but leaves moves, inserts and removals for a later run (the live guard
    of T14).
  [js-morph-keys, repo-dom-morph-attrs]
- [ ] **T17** Bounded matching (dom.js:33-60). For each unkeyed desired node the order is:
  1. The cursor is `isEqualNode` → keep it.
  2. The cursor has the same shell → recurse.
  3. Look ahead at most 8 siblings for an `isEqualNode`. Compare tags first and `isEqualNode` last; skip
     whitespace-only text, keyed nodes, `data-ds-keep` nodes and pending removals as candidates. On a hit, remove
     the nodes in between (through `onRemove`).
  4. Same tag → patch in place.
  5. Insert.

  A far identical `<td></td>`, divider or whitespace node can no longer delete the siblings before it, and the cost
  stays linear. [js-morph-greedy]
- [ ] **T18** Focus. `target.ownerDocument.activeElement` and its ancestors are never replaced or removed by a
  shell difference: they are always patched in place. A focused control keeps its live `value`, `checked` and
  selection (the attributes are synced, the properties are not), so focus, caret and IME composition survive a
  re-render on every keystroke. [js-morph-focus]
- [ ] **T19** Hooks and kept nodes.
  - `onInsert(node)` runs after a new element is inserted.
  - `onRemove(node)` may return a Promise. The node then stays as a pending removal (`inert`, `aria-hidden`,
    `data-ds-leaving`) that later morphs skip as cursor and as match, and is removed when the Promise settles.
  - Nodes with `data-ds-keep` are never the cursor, never removed (also not by the trailing loop) and do not count
    as a difference.
  [js-morph-hooks, js-morph-indicator]
- [ ] **T20** The indicator survives a morph (`src/js/indicator.js`).
  - `createIndicator` (indicator.js:22-29) sets `data-ds-keep` on the `.ds-indicator` span.
  - `place()` (indicator.js:40) re-prepends the span when `indicator.parentNode !== track`. It jumps once, which is
    right after a foreign re-render.
  - P4's indicator rewrite keeps both.
  [controls-indicator-morph-removes, js-morph-indicator]
