# P7: View Transitions and scroll-driven effects (1.5.0)

P7 adds the motion between views (D15) and the motion that follows scrolling (D5, D33). Same-document navigation
gets `DS.motion.transition()`: fade-through between top-level destinations, shared axis X for forward and back, and
a container transform from a card or row into its detail. The top bar stays still, and the drawer and segmented
indicators glide into place. Where View Transitions are missing, or when `.ds-theme` is not on `<html>` (an
embedded widget), the new view fades through with `.ds-enter--swap` (D30). Multi-page apps opt in with
`css/optional/view-transitions.css`. Scroll-driven animations replace the `data-scrolled` listener where the
engine has them: the panel hairline, the top bar tint (D33), the sheet head hairline, the table edge fades, and
an opt-in reveal on scroll. `data-scrolled`, set by an IntersectionObserver sentinel, stays the fallback.

Depends on:
- P1: `@layer` order, `--ds-ease-spatial` and the duration ladder, the keyframe catalogue with individual
  `translate`/`scale`, `@property` at top level, the Progressive feature regex in `test/css.test.js`;
- P2: `enter()` and its generation token, `settled()`, `motionDuration()`, the `fallback` Playwright project;
- P4: indicator stretch, item observation and instant first placement; the drawer entering on X; the state-driven
  top bar tint and its hook `--ds-topbar-scrolled-bg`;
- P5: `DS.overlay`, native `<dialog>` and the sheet;
- P6: the table and card work.

Ships as **1.5.0**. Everything is additive: the top bar tint and its opt-out hook `--ds-topbar-scrolled-bg` shipped
in P4 (1.2.0); P7 only drives the tint by scroll where supported. Line numbers refer to `src/` at `05aaeb3`; P1-P6 move them, so find the rules by their
selector. Canonical names, values and APIs come from [motion-2.md](../motion-2.md). Where this file and that file
disagree, that file wins.

## Tasks

### `DS.motion.transition()` (`src/js/motion.js`)

- [ ] `export function transition(update, { type = 'fade-through', from } = {})`. `type` is one of
  `'fade-through'`, `'forward'`, `'back'` and `'container'`; any other value throws a `TypeError`. `update` may be
  synchronous or async. It may return (or resolve to) the element that holds the new content. That element is the
  container target and the fallback's entrance target. The helper returns a Promise that resolves once the update
  has run and the motion has finished, also when the motion is skipped. It rejects when `update` throws, after it
  has cleaned up. [core-js-view-transitions, js-view-transitions, repo-opp-view-transitions]
- [ ] View Transition path. It runs only when `typeof document.startViewTransition === 'function'` **and**
  `document.documentElement.classList.contains('ds-theme')`. Only then do the tokens reach the `::view-transition`
  tree, and only then is the snapshotted document the system's own page.
  - Set `data-ds-vt="<type>"` on `<html>` before `startViewTransition()`. The CSS keys the names and the
    direction on this attribute. View-transition `types` are not used: one mechanism, which also works in Safari
    18.0.
  - `container`: write `from.style.viewTransitionName = 'ds-container'` before the snapshot. In the update
    callback, clear it on `from` and set it on the returned target. If `from` is missing or disconnected, or the
    update returns nothing, the transition falls back to a plain fade-through.
  - A transition that is still running is skipped with `skipTransition()` before the new one starts. Updates
    always run, and they run in call order.
  - Watchdog: an update that has not resolved after `motionDuration(root, '--ds-dur-long')` gets
    `skipTransition()`, so a slow render never freezes input for long. The docs say to fetch first and then call
    `transition()` with a quick swap.
  - On `finished`, whether it completed or was skipped, remove `data-ds-vt` (only if this call is still the
    latest) and every inline `viewTransitionName` the helper wrote.
  [core-js-view-transitions, js-view-transitions, repo-opp-view-transitions]
- [ ] Fallback path (D30): no View Transitions, or `.ds-theme` not on `<html>`. Run `update()` at once, then
  `enter(target, 'swap')` on the returned element. Without one, use the first element child of the `.ds-view`
  that is `.ds-theme`'s descendant; with neither, swap without motion. Nothing waits before the update (no
  `.ds-view--leaving` step), so the user never waits. Rapid calls land on the latest view through `enter()`'s
  generation token (P2). [js-view-transitions, repo-opp-view-transitions, core-js-view-transitions]
- [ ] Module header, under "Progressive:": `startViewTransition`, with the fallback named. The JSDoc says
  `transition()` is for navigation only (destinations, drill-downs, record changes), never for data refreshes,
  polling or typing. It also says no component calls it, except `DS.overlay.open` with `container: true`
  (below). [core-js-view-transitions]

      from `var(--ds-distance-xl)`;
    - both movements run over `--ds-dur-slow` on `--ds-ease-spatial`, because the two images travel on one axis;
    - `back` mirrors both signs.
  - Container transform, `[data-ds-vt="container"]`:
    - `::view-transition-group(ds-container)` moves over `--ds-dur-long` on `--ds-ease-spatial`;
    - old: `ds-fade-out` over `--ds-dur-fast`; new: `ds-fade-in` over `--ds-dur-medium`, delayed
      `--ds-dur-instant`; both on `--ds-ease-in-out`;

      detail.
  - No new keyframes. Add a row to the `docs/motion.md` utilities table that names these uses of `ds-fade-*`,

  [core-js-view-transitions, layout-view-swap-vt, repo-opp-view-transitions]

## Done when

- `DS.motion.transition()` runs all four types in every engine that has same-document View Transitions (at least
  Chromium and WebKit). The `fallback` project and any engine without the API prove the `.ds-enter--swap` path. A
  page without `html.ds-theme` never calls `startViewTransition`.
- The top bar never animates in any transition. The drawer and segmented indicators glide in SPA transitions and in
  MPA navigations, and never jump when the transition ends.
- `dist/ds.css` contains no `@view-transition`. `dist/css/optional/view-transitions.css` exists, is checksummed and
  is documented.
- The hairlines, the top bar tint and the table edge fades follow scroll where supported and fall back to
  `data-scrolled` or the static mask elsewhere. No styleguide scroll handler writes attributes per event.
- `.ds-reveal--scroll` never hides content where `view()` is unsupported, or in print.
