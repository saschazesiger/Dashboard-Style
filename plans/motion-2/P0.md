# P0: Tooling and safety net (no version, `dist/` unchanged)

P0 builds the tooling every later phase depends on: Playwright as a pinned devDependency, a browser harness for
Chromium, Firefox and WebKit, one shared motion helper module, a capability spike that decides the risky P2/P3/P5/P6
designs, screenshot and timeline baselines of today's state, and every known bug written down as a `test.fail` marker
that its fixing phase turns green. It also fixes three test-suite weaknesses, hardens CI, makes the styleguide
theme switch deterministic and adds an interim slow-motion switch to the styleguide.

It depends on nothing. Starting point is commit `05aaeb3`: `npm run check` passes with 100 tests in 14 suites and
reports "dist/ is up to date (39 files)". P0 changes **nothing in `src/`, `dist/`, `fonts/` or `themes/`**, and the
version stays `0.1.0`, so it has no CHANGELOG section. It goes to `main` like every phase (D4), and because projects
vendor only `dist/`, the nightly update has nothing new to pick up.

Canonical names, values and APIs come from [motion-2.md](../motion-2.md). Where this file and that file disagree,
that file wins.

### Helper module `test/browser/helpers/motion.js`

- [ ] This is the one shared helper module (motion.js, "Verification"). It imports only `node:*` (`node:assert`)
  and never `@playwright/test`, so its pure series checks are unit-testable under `node --test`. Page functions take
  Playwright `page` or `locator` objects as arguments and run their code through `evaluate`. Every spec imports
  this module. No other helper file is created: no `motion.mjs`, no `test/browser/motion.js`, no per-area
  helpers.
  - `ready(page)` waits for `document.fonts.ready` and, on the styleguide, for `html[data-sg-ready]`.
  - `timeline(locator, { subtree, names })` maps `getAnimations()` to `{ type: 'animation' | 'transition' |
    'script', name (animationName, transitionProperty or id), pseudoElement, duration, delay, easing, iterations,
    direction, fill, playState, currentTime }`, read from `effect.getTiming()` and `getComputedTiming()`. Infinite
    animations report `iterations: Infinity`.
  - `freeze(page)` pauses every `document.getAnimations()` entry, pseudo-elements included.
    `seek(page, ms | { progress })` sets `currentTime` on all of them. Both are used for mid-animation screenshots
    and seek-based sampling.
  - `sample(locator, props, times, { pseudo })` seeks to each time and then reads `getComputedStyle`. It returns
    numbers: opacity, the `transform` matrix decomposed into translateX/Y and scaleX/Y, the individual
    `translate`/`scale`/`rotate`, `border-radius`, `outline-offset`, `width`, `clip-path` inset values and
    registered custom properties.
  - `rafSample(locator, props, ms, { pseudo })` reads the same values each animation frame in real time. Use it
    only for interruption, with tolerances.
  - `settle(page, { timeout = 3000 })` runs `Promise.allSettled` over the `finished` promises of every finite
    animation and ignores infinite loops.
  - `setSpeed(page, factor)` uses the `?speed=` playback-rate bridge in P0. P1 switches it to
    `--ds-time-scale = 1 / factor`.
  - `press(locator, { holdMs, x, y, pointer: 'mouse' | 'touch' })` sends real pointer events (`page.mouse` or the
    touchscreen) at an offset inside the element.
  - `focusByKeyboard(page, locator)` moves focus with the Tab key, so `:focus-visible` matches.
  - Pure checks:
    - `expectMonotonic(series, { direction })`
    - `expectWithin(series, min, max)`
    - `peakRatio(series, from, to)` returns the overshoot as a ratio of travel.
    - `expectPeakAtMost(series, 1.05, { from, to })`
    - `expectSettles(series, target, tolerance = 0.005)`
    - `expectContinuous(series, { factor = 2, floor })`: no step larger than `factor` times the median step plus
      an absolute `floor` for rAF jitter, so an interruption never jumps.
    - `expectEndState(locator, styles)`

### Capability spike `test/browser/spike.spec.js`

- [ ] One test per capability, run in all three engines on `fixtures/spike.html`. Each test asserts the capability
  that a later design relies on. Where an engine lacks it, mark the test with
  `test.fail(browserName === '<engine>', 'spike: <capability>')` and note the consequence. Record every result in
  the "Capability spike" table in `test/browser/README.md` (capability, engine, result, design consequence). If a
  result changes a later design, add a note to the phase file concerned before that phase starts. The tests:
  1. **Interruption mechanism (D21, P2).** A CSS animation that moves `translate` and `opacity` is stopped at 40%.
     The test reads the computed values, calls `cancel()` and then
     `el.animate([current, target], { duration, easing })`. Assert that the first sampled frame equals the values
     read (`expectContinuous`) and that no un-animated frame shows between `cancel()` and `animate()`. Run it once
     with a `linear(...)` easing and once with a cubic one. Record whether `animate()` accepts `linear()` or throws
     a `TypeError` (then the cubic fallback is used).
  2. **`KeyframeEffect.setKeyframes()` and `updateTiming()` on a running `CSSAnimation`.** This is the alternative
     that was considered. Record whether it works and whether the element keeps following later CSS changes. This
     is for the record only: the authority uses mechanism 1.
  3. **Individual properties.** A `translate` keyframe composes with an inline `transform` (the tooltip and the
     indicator): at 10% of the entrance the box is at the inline position plus the keyframe offset. Also record
     whether `composite: 'add'` on `translate` works, which FLIP retargeting can use.
  4. **Pseudo-element animations.** `document.getAnimations()` lists `::before`/`::after` animations with
     `effect.pseudoElement`. After `freeze()`/`seek()`, `getComputedStyle(el, '::before')` reflects the seeked
     time. This gates the P6 loader and progress tests.
  5. **`appearance: none` checkbox and radio (D23, P3).** Draw `::before`/`::after` on the 18px native input and
     put a 10px `box-shadow` halo on it. Check that it renders in all engines: check with a screenshot crop and
     with the computed `content`. Also check whether the halo is clipped in a `.ds-table` wrapper with `overflow`.
  6. **Rows (D7, P2/P6).** A `translate` animation on a `<tr>` moves the painted cells (sample a cell's rect).
     `position: relative` on a `<tr>` contains an absolutely positioned child span, which the ripple needs (a known
     WebKit quirk). If containment fails, rows get no ripple but still FLIP.
  7. **Registered properties (P1).** With `@property --spike-scale { syntax: '<number>'; inherits: true;
     initial-value: 1 }` and `animation-duration: calc(250ms * var(--spike-scale))`, setting the property to 10 on
     an ancestor multiplies `getComputedTiming().duration`, and the same holds for `animation-delay`. A second
     property registered with `inherits: false` does not reach a child.
  8. **Focus snap (D24, P3).** An `outline-offset` transition from 4px to 2px on `:focus-visible` shows a solid
     outline from the first frame. A `.ds-enter` animation running on the same element keeps playing, so a
     transition cannot conflict with `animation`.
  9. **Closing `<dialog>` (P5).** After `close()`, a rule that keeps the dialog `display: block;
     position: fixed; z-index: <high>` during a 200ms exit animation keeps it painting above a `position: sticky`
     page element in every engine.
  10. **Skeleton wave (D11, P6).** Two bones at different x positions with `background-attachment: fixed` and an
      animated `background-position` show the same wave phase: compare pixel columns at the same viewport x. Also
      record whether the phase holds inside a transformed (entering) parent.
