# P4: Navigation (1.2.0)

Goal: the navigation parts move like M3 Expressive without ever getting in the way. The sliding indicator stretches
toward its target (the leading edge leads, the trailing edge follows), lands on the spatial spring, takes longer for
longer jumps (capped), is drawn by `clip-path` instead of `width`/`height`, follows its items by itself and survives
`morphHtml`. The drawer comes back on the X axis, the modal drawer opens on the spring and closes accelerating without
ever showing a gap at the screen edge, labels change colour in step with the pill, the segmented switch keeps its
width, the top bar tints on scroll (D33) and `.ds-view` keeps a stable scrollbar gutter. Decisions: D1, D2, D14, D16
(mirrored for the modal drawer), D20, D21, D29, D30 (the manual swap sequence; P7's fallback keeps only its entrance), D33.

Depends on: P0 (browser harness, `test/browser/helpers/motion.js`, the `test.fail` markers for the indicator and the
drawer), P1 (`@layer`, `--ds-ease-spatial`, `--ds-ease-exit`, `--ds-dur-micro`/`--ds-dur-long`, `--ds-time-scale`, the
animated-property allowlist with its temporary `.ds-indicator` width/height exception, the exit ratio test), P2
(`motionDuration`, `travelDuration`, `settled`, `data-ds-keep` in `morphHtml` plus the re-prepend in `place()`,
`DS.ripple` spans marked `data-ds-keep`), P3 (press morph and focus snap on `.ds-drawer__item` and
`.ds-segmented__option`, the pressed-pill rule). P4 keeps the scroll lock as the documented page recipe
(`body.ds-no-scroll`); `DS.overlay` and `lockScroll` arrive in P5.

Ships as **1.2.0** (minor): the indicator API only gains an option, every changed look has a hook or keeps working.

Scope note: the phase table names a rail. The repository has no navigation rail and no decision or finding asks for
one (D26 lists the new parts), so P4 adds none; vertical tracks (the drawer list) are covered by the indicator work.

    `--ds-indicator-radius`, each `syntax: '<length>'; inherits: false; initial-value: 0px`.
  - `.ds-indicator`: `translate: var(--ds-indicator-x, 0) var(--ds-indicator-y, 0)` (replaces `transform:
    translate3d(...)`), `width: var(--ds-indicator-w, 0)`, `height: var(--ds-indicator-h, 0)`, none of them
    transitioned; `clip-path: inset(var(--ds-indicator-t) var(--ds-indicator-r) var(--ds-indicator-b)
    var(--ds-indicator-l) round var(--ds-indicator-radius))`. Delete the `transform`, `width`, `height` entries of
    today's transition (L25-29).
  - `.ds-has-indicator > .ds-indicator[data-glide] { border-radius: 0; }`, so a box radius set by a project class never
    cuts into the painted area while the box is the union of two items.
  - Shape: component classes set the radius through the variable: `.ds-drawer__indicator { --ds-indicator-radius:
    <the half-height expression P3 gives .ds-drawer__item's border-radius> }` instead of `border-radius`
    (shell.css L454-457); `.ds-segmented__indicator` sets none (the container clips its ends). P3's pressed-pill rule
    (`.ds-has-indicator:has(.ds-drawer__item[aria-current="page"]:active) > .ds-drawer__indicator`) keeps its selector
    and now sets `--ds-indicator-radius` to the pressed value; `--ds-indicator-radius` is in the indicator's transition
    list with the press timing P3 uses for the drawer item.
    - Note (from the P3 review): P3's pressed-pill rule restates the indicator's whole transition list (only the
      radius entry on `--ds-dur-micro` `--ds-ease-out`), because the item a click has just made active is still
      `.ds-pressed` while the pill glides to it; its `.ds-indicator--instant` twin and the modal-drawer twin keep the
      radius alone. Keep all three in step with `.ds-indicator` when it moves to translate / clip-path, and drop the
      rule's `ANIMATED_PENDING` entry in test/css.test.js with the `.ds-indicator` one.
  - Project indicator classes that only set `border-radius` keep working: at every rest placement, if the computed
    `--ds-indicator-radius` is `0px` and the computed `border-top-left-radius` is larger, JS writes that value (px,
    capped at half the item's smaller side) inline as `--ds-indicator-radius`.
  - Rest state: box = the active item's rect in the track's scroll coordinates (keep L92-93's `- clientLeft +
    scrollLeft` / `- clientTop + scrollTop`), insets `0px`, no `data-glide`: a plain rounded pill.
  - `.ds-indicator--instant { transition: none }` and `[data-empty] { opacity: 0 }` stay public.
  - No `--plain` fallback: `@property` is baseline (D28). [controls-indicator-layout-props]
- [ ] **Directional stretch with a spring landing (D20), on by default.** On a glide JS:
  - computes the travel between the centres of the painted rect it leaves (`from`) and the target item (`to`), sets
    `data-dir` on the span to `left`, `right`, `up` or `down` from the sign of the dominant axis;
  - writes `--ds-indicator-dur: <travelDuration(track, distance)>ms` on the **track** (inline; already includes
    `--ds-time-scale`, so CSS never multiplies it again; the labels read it, see below);
  - step 1, with `.ds-indicator--instant`: sets `data-glide`, the box (`--ds-indicator-x/-y/-w/-h`) to the union of
    `from` and `to` widened on the travel axis by an overshoot margin `M = ceil(OVERSHOOT × distance) + 1px`
    (`OVERSHOOT = 0.05`, the 1.05 peak contract; clamped to `0 … track.scrollWidth/scrollHeight` so the box never adds
    scroll range), and the four insets so the painted area still equals `from`; then one style flush
    (`getComputedStyle(indicator).getPropertyValue('--ds-indicator-t')`);
  - step 2, without `--instant`: sets the insets of `to`. CSS transitions the edges:
    `transition-property: --ds-indicator-t, --ds-indicator-r, --ds-indicator-b, --ds-indicator-l,
    --ds-indicator-radius, opacity`, edges on `var(--ds-indicator-dur, var(--ds-dur-medium)) var(--ds-ease-spatial)`,
    opacity on `var(--ds-dur-fast) var(--ds-ease-in-out)`. The trailing edge waits
    `var(--ds-indicator-lag, var(--ds-dur-micro))`: `[data-dir="right"]` delays `-l`, `left` delays `-r`, `down`
    delays `-t`, `up` delays `-b` (one `transition-delay` list per rule; `--ds-stagger` is not used);
  - when every edge transition of this glide has settled (`Promise.allSettled` of their `finished`, guarded by a
    per-indicator generation), it collapses to the rest state with `--instant` (no visual change) and removes
    `data-glide` and `data-dir`.
  - The pill therefore stretches toward the target, its lead edge passes the target by at most 5 % of the travel and
    settles; the drawer (vertical, long) and the segmented switch (horizontal, short) behave the same way, only the
    distance differs. At the segmented switch's outer ends the container's `overflow: hidden` clips the overshoot; that
    is accepted. [controls-indicator-stretch, js-indicator-stretch]
- [ ] **Duration from distance.** `travelDuration(track, px)` (P2, the one function for FLIP and the indicator) gives
  `--ds-dur-medium` for a neighbour hop up to `--ds-dur-slow` (cap) for long jumps; no literal, no second formula in
  `indicator.js`. `--ds-indicator-dur` joins `RUNTIME` in `test/css.test.js` (L32). [controls-indicator-distance-duration]
- [ ] **Glide decision without a time window.** Delete `glideUntil`, `Date.now()` and the 600 literal (L72-76, L87-89).
  A placement glides when the active item differs from the last placed one, or when the indicator still has a running
  `CSSTransition` on one of its edge properties (`indicator.getAnimations()`); then it retargets from the **current**
  painted rect (computed edge values, read before `--instant` is set) to the new target, so a resize or a second click
  mid-glide continues without a jump (D21). A resize with nothing running jumps (rest state). The first placement
  always jumps. [controls-indicator-glide-window, js-indicator-glide-window, repo-indicator-glide-constant]
- [ ] **Appear and disappear as their own case.** When an active item appears after an empty state (not the first
  placement), the box is set to the item, the inline-axis insets (`-l`, `-r`) start at half the item's width with
  opacity 0, then open to `0px` over `--ds-dur-medium` (written as `--ds-indicator-dur`) on the spring while opacity
  fades in over `--ds-dur-fast`: the pill grows from the item's centre. When the active item goes away, the span gets
  `data-empty` and the inline-axis insets close to the centre; `.ds-indicator[data-glide][data-empty]` sets the edge
  durations to `--ds-dur-fast` and their curve to `--ds-ease-in`. No `@starting-style`: the first placement on load
  still jumps (across page loads P7's view transition moves the pill). The `--instant` ambiguity of L32-38 is gone
  because every case sets its own timing. [controls-indicator-appear]

### Indicator: observing and lifecycle (`src/js/indicator.js`)

- [ ] **Observe the track, its items and the active item.** Use `track.ownerDocument` and its `defaultView` for
  `ResizeObserver`, `MutationObserver`, `requestAnimationFrame` and `getComputedStyle`. The `ResizeObserver` watches the
  track, every element child of the track except the indicator, and the placed item (unobserve the old one,
  observe the new one on change); it re-syncs its set after a `childList` change. So a badge or a wrap in an earlier
  item, a group expanding above, or the active label growing inside the fixed-height `.ds-drawer__list` re-places the
  pill. All callbacks are batched into one `requestAnimationFrame` (one pending frame per indicator). Fonts:
  `ownerDocument.fonts.addEventListener('loadingdone', …)` in addition to the one-shot `ready`.
  [controls-indicator-item-resize, js-indicator-observe]
- [ ] **Self-updating (D20), on by default.** A `MutationObserver` on the track (`subtree: true`, `childList: true`,
  `attributeFilter: ['aria-current', 'aria-pressed', 'aria-selected', 'aria-checked']`, never `class`, because
  `place()` toggles classes) schedules `place(true)` in the same rAF batch. Records whose target is the indicator, and
  `childList` records whose added and removed nodes all carry `data-ds-keep` (the indicator, `DS.ripple` spans), are
  ignored, so neither the indicator's own writes nor a ripple re-places it. New option `observe` (default `true`);
  `createIndicator(track, { active, className, observe: false })` turns the observer off. `update()` stays and is
  harmless when the observer already moved the pill (a placement on the same running target keeps gliding).
  [controls-indicator-auto-observe, js-indicator-observe]
- [ ] **`destroy()` is final.** A `destroyed` flag turns `place()`, the rAF batch, the `fonts.ready` callback and the
  `loadingdone` listener into no-ops; `destroy()` disconnects both observers, cancels the pending frame, removes the
  fonts listener, the span, `.ds-has-indicator` and the track's `--ds-indicator-dur`. [controls-missed-7,
  js-indicator-observe]
- [ ] **Morph-safe.** P2 marks the span `data-ds-keep` and re-prepends it in `place()`; P4 only makes sure the observers
  keep working after `morphHtml(track, html)` (the `childList` re-sync above) and covers it with a browser test.
  [js-indicator-observe]
- [ ] **Header comments.** `indicator.css` L1-9: "The leading edge leads and the trailing edge follows on the spatial
  spring; the travel time grows with the distance (capped at `--ds-dur-slow`); the pill is drawn by `clip-path` on a
  box, never by animating `width`/`height`", plus the markup, `data-glide`, `data-dir`, `data-empty`, the hooks
  `--ds-indicator-radius` and `--ds-indicator-lag`. `indicator.js` L39-59: options (`active`, `className`, `observe`),
  what is observed, first placement and resizes jump, retargeting, destroy. [controls-indicator-stretch]
